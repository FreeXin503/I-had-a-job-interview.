1. 项目背景与差异化破局策略
――――――――――――――――――――――――――――――――――――――――
在当前AI模拟面试赛道中，多数竞品采用云端数字人推流方案（如实时视频流生成），虽然具备高精度的面部肌肉对齐，但给团队带来了极为高昂的服务器并发成本、长达数秒的推流延迟，以及微信小程序端由于高带宽消耗引发的手机发烫、卡顿闪退等毁灭性体验。同时，过于逼真的虚拟人往往会触发用户的「恐怖谷效应」，加剧用户的容貌焦虑与镜头恐惧感。
本产品「面了个试」采取颠覆性的**‘重脑轻面’**破局策略。我们将全量算力与成本留给 **DeepSeek** 的高智商逻辑深度，在视觉层采用微信原生 **XR-Frame** 技术在手机端侧直接渲染轻量化 3D 虚拟头像。通过本地算法将音频振幅动态映射到模型的嘴部开度（Morph Targets），实现免去昂贵云端对嘴模型的“低成本、零延迟、高流畅”动态交互，从而将‘没有仿真真人脸’的硬伤直接转化为‘沉浸式科幻全息/高心理安全感盲审’的独特卖点。

2. 产品总体架构与用户旅程
――――――――――――――――――――――――――――――――――――――――
「面了个试」核心产品架构包含四大核心功能模块，通过一条高度游戏化的链条将用户闭环在系统内部。
1. 拟真投递入口：支持微信一键上传 PDF 简历、照片识别，或直接同步求职意向，通过 DeepSeek 瞬时提取关键词。
2. 3D全息面试舱：本地端侧拉起 3D 面试官模型，接收流式大模型音频进行声波级嘴型动态同步。
3. 潜台词解密复盘：面试后不仅给出基础评分，更首创‘面试官心理学潜台词转译画布’。
4. 魔性裂变关卡：致敬《羊了个羊》的难度陡升设计，刺激用户通过‘分享求助群友’、‘一键代答’完成病毒式传播。
【用户核心生命周期路径】
用户主链路流转：
用户进入首页 -> 选择或导入简历 -> 选择面试官性格人设(如温柔严姐/硬核老张) -> 触发模拟‘微信来电/会议邀请’ -> 进入3D全息互动界面 -> 完成多轮追问 -> 触发淘汰或晋升动效 -> 查看逐句潜台词解密画布 -> 分享被虐战绩或高分名册至微信群。

3. 核心模块详细功能设计
――――――――――――――――――――――――――――――――――――――――
■ 3.1 微信端侧 3D 全息面试舱 (XR-Frame 渲染与动态嘴型方案)
本模块为核心交互阵地，旨在用极低的设备资源与带宽代价，营造最具冲击力的“赛博会议”交互体验。
1. 3D渲染引擎：【技术实现细节】
放弃常规视频组件，采用微信原生小程序 3D 开发框架 XR-Frame。在本地直接异步加载 `.gltf` 或 `.glb` 格式的超轻量低模职场人物（模型文件大小严格控制在 3MB 以内）。
2. 本地嘴型联动机制（重点）：【动态同步算法】
系统不需要高昂的云端语音对嘴模型。通过小程序本地音频播放器的实时音量包络（VAD / Amplitude Envelope）捕捉当前播放声音的振幅 $A(t)$。将振幅线性映射到 3D 模型的嘴部开合度权重（Morph Target Weight: `Mouth_Open`）上。为了使张口效果更自然、不显机械僵硬，加入微小高频正弦扰动波，公式如下：
M_open(t) = Min(1.0, α × [A(t) - A_floor] / [A_ceil - A_floor]) + ε × sin(2πft)
其中，α 为全局振幅增益因子，A_floor 为环境噪音底噪阈值，A_ceil 为最大音频目标包络值，ε 则是用于模拟真人眨眼、微表情变化或微小嘴唇颤动的高频噪声因子（频率 f 设为 3Hz~5Hz）。前端框架每帧（约16.6ms）执行一次更新，确保嘴巴张合完全随声音起伏自适应播放。
3. 视觉包装破局：【全息特效包装】
为了防止用户察觉嘴型没有精准对齐发音（如B, P, M等爆破音的闭嘴动作），3D 渲染图层上层叠加一个**‘全息粒子滤镜（Hologram Filter）’**。包含绿荧光/冷蓝色的横向扫描线、零星离散的赛博微观粒子，以及由于‘网络不稳’带来的 100ms 级别周期性轻微画面闪烁抖动。通过 UI 的视觉心理暗示，让用户天然接受‘这是远程赛博全息通信，因此信号传输导致嘴型存在动态偏差’的设定，反向提升科技高级感。

■ 3.3 逐句“面试官心理潜台词”转译画布
传统面试产品只给“你的回答很流利”等假大空的评语，无法解决核心痛点。本产品利用 DeepSeek 打造绝对差异化的核心壁垒看板。
1. 复盘画布设计：【核心交互展现形式】
面试结束后生成微信卡片式瀑布流。左侧为用户的完整语音转文字记录，右侧为对应的**‘面试官潜台词破译窗’**与**‘高分重塑话术’**。
【复盘画布数据流转示例】
【用户原话】：我上个项目主要是我组长带我做的，我主要负责写了前台的三个页面和对应的接口联动...
【DeepSeek转译潜台词】：这是一个缺乏主动性、抗压能力弱的纯执行工具人。遇到复杂架构或独立攻坚时大概率会崩盘，没有思考过业务全貌，培养价值低。
【高分话术重塑】：在这个项目中，我独立承接了前台核心交互模块的研发。在组长的架构指导下，不仅完成了3个核心页面的端到端联动，还主动优化了接口吞吐，使前端加载耗时降低了15%...

■ 3.4 游戏化防防撤退机制与裂变系统
结合小程序高裂变属性，命名致敬经典。设置极具网感的游戏化关卡：
• 第一关：【初露锋芒】(1分钟自我介绍)。通过率 99%，只要能开口说话就稳过，通过后发放高大上的‘大厂绿卡通关凭证’，极易触发用户分享朋友圈自嗨。
• 第二关：【地狱大乱斗】(10分钟硬核考官连环轰炸)。通过率仅 0.1%。失败后直接弹出魔性文案弹窗：‘你已被硬核老张体面地抬出面试间，死因：高并发底层原理编造痕迹过于明显。’
【救命裂变机制】：在第二关被虐出局后，用户可以一键将面试录音与复盘画布分享到微信群，发起‘群友救命/导师代答’。群里任何人点击即可收听被虐现场，并能亲自上阵打字或语音代答一题，代答成功可帮原用户‘复活’增加血量。以此完成极高的社群病毒式二次扩散。
4. 技术要求与非功能性需求规范

■ 4.1 DeepSeek 交互工程与数据流控制
为保证语音通话无卡顿、零冷场，系统必须严格执行流式传输（Stream Line）管线：
流转阶段	技术实现方案	硬性性能指标 (KPI)
1. 用户语音截断	前端通过 VAD (语音活动检测) 监测到用户连续停顿超过 800ms，即刻自动截止录音并上推。	端侧响应时间 < 200ms
2. 大模型流式输出	调用 DeepSeek API, 开启 stream=true 模式。限制单次回复长度在 60-120 字口语话术，严禁Markdown多级列表。	首字返回时间 (TTFB) < 600ms
3. 实时TTS合成	采用‘流式流出、切句合成’策略。DeepSeek每输出一个完整句子（遇到逗号、句号），即刻送入高并发TTS引擎合成立体音轨。	分句合成时延 < 300ms
4. 本地前端消费播放	前端构建动态双音频缓冲区（Audio Buffer Queue），第一句合成完毕立刻开播，第二句在后台无缝拼接播放。	整体语音互动循环停顿 < 1.5s

■ 4.2 设备兼容性与端侧性能保障
• 帧率控制：由于使用了 XR-Frame 3D 引擎，在低端机型（如 iPhone 11、老款安卓机）上，系统检测到发热或降帧时，应自动降低模型抗锯齿级别，并将全息粒子线动态特效降低 50% 密度，确保帧率稳定在 45fps 以上。
• 包体积限制：3D 基础男/女高频模型必须放入微信小程序分包中异步下载，或者托管于 CDN，主包体积保持在 1.5MB 以内，实现“秒开”触达用户，碾压需要长时间下载 App 的重型面试竞品。
